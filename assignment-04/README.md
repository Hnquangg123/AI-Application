# Assignment 04 - Efficient Azure OpenAI API Usage

This submission demonstrates Azure OpenAI function calling, list-based batch processing, exponential-backoff retries, output validation, and graceful per-item error handling. The selected topic is **travel itinerary planning**.

## Files

- `assignment04_azure_openai.py` - the complete single-file Python solution
- `README.md` - setup, design notes, and representative sample results

## Requirements

- Python 3.9 or newer
- An Azure OpenAI resource and a deployed chat model that supports function calling
- `openai` and `tenacity`

Install the dependencies:

```bash
python -m pip install openai tenacity
```

## Configuration

The script reads credentials from environment variables so secrets are not stored in source code.

PowerShell:

```powershell
$env:AZURE_OPENAI_ENDPOINT = "https://YOUR-RESOURCE.openai.azure.com/"
$env:AZURE_OPENAI_API_KEY = "YOUR-API-KEY"
$env:AZURE_DEPLOYMENT_NAME = "YOUR-DEPLOYMENT-NAME"
```

Bash or zsh:

```bash
export AZURE_OPENAI_ENDPOINT="https://YOUR-RESOURCE.openai.azure.com/"
export AZURE_OPENAI_API_KEY="YOUR-API-KEY"
export AZURE_DEPLOYMENT_NAME="YOUR-DEPLOYMENT-NAME"
```

The API version is set to `2024-07-01-preview` to align with the assignment specification.

## Design Choices

### Function calling

The script uses the current Chat Completions function-tool format: `tools`, a named `tool_choice`, and the returned `message.tool_calls`. The `generate_itinerary` schema requests a destination, trip summary, duration, and one structured plan for every day.

Tool arguments are JSON text generated by the model, so the script parses and validates them before accepting an itinerary. It checks the required text fields, requested duration, number and order of days, titles, and activity lists.

### Batch processing

`batch_process()` accepts a list and processes each item sequentially. Every item produces either a success record or an error record. An error for one destination is logged but does not prevent later destinations from being processed.

This assignment uses list-based batching rather than the separate asynchronous Azure Batch API. No fixed sleep is added between successful calls; that would unnecessarily slow the batch. Throttling and other transient failures are handled by targeted retries.

### Retries and exception handling

`call_openai_function()` uses tenacity decorators to retry:

- `RateLimitError`
- `APIConnectionError`
- `APITimeoutError`
- `InternalServerError`

Retries use `wait_random_exponential(min=1, max=10)` and stop after five attempts. Tenacity logs each wait before retrying and reraises the last error after the final attempt. Input errors and invalid model output are not transient, so they are not retried; instead, they become a per-item error result.

The program exits with code `1` for missing configuration, `2` if the batch finishes with one or more failed items, and `0` when every item succeeds.

## Challenges and Solutions

1. **The assignment example uses an older API style.** The solution uses the modern function-tool request and response fields while preserving the required function-calling behavior.
2. **Function arguments are model-generated JSON.** The solution validates the parsed structure instead of assuming it is correct.
3. **Rate limits and temporary service failures can interrupt batches.** Tenacity retries only transient OpenAI exceptions with randomized exponential backoff.
4. **One invalid item should not crash the whole run.** Each call is wrapped by the batch processor, which records the error and continues.
